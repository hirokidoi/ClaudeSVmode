# macOS の検証

## 検証コマンド

SV はここから `test_commands` を組み立てる。名前・パスは、プロジェクトの設定に合わせる。

| kind | コマンド | 用途 |
|---|---|---|
| build | `xcodegen generate` | XcodeGen の構成で、プロジェクトを生成する。ビルドの前に置く |
| build | `xcodebuild -scheme <名前> -derivedDataPath <ビルド出力> build` | アプリのビルド。出力先を指定して、成果物の場所を決める |
| build | `swift build --package-path <パッケージ>` | Swift パッケージのビルド |
| test | `swift test --package-path <パッケージ>` | パッケージのテスト。サブパッケージは `--package-path` で指定する |
| test | `xcodebuild test -scheme <名前> -derivedDataPath <ビルド出力>` | アプリのテストターゲット |
| launch | 下の例 | 起動確認 |

起動確認 (launch) は、起動、生存の確認、停止を 1 つのコマンドで完結させる。画面・許可ダイアログは確かめない。

```
bash -c '<成果物のパス>/Contents/MacOS/<実行ファイル> & pid=$!; sleep 5; kill -0 "$pid"; rc=$?; kill "$pid" 2>/dev/null; wait "$pid" 2>/dev/null; exit $rc'
```

## 実行の方針

- 重いテスト (実際のエンコードなど) は、別のターゲットかフィルタに分ける。範囲はプロジェクトの規約に従い、規約が無ければ、途中は変更に届くテスト、完了前は全件にする
- 警告の件数を報告する前に、クリーンビルドにする。増分ビルドでは、警告が出ない
- 出力が大きいときは、全体をファイルに保存してから検索する。出力を絞って、失敗行を落とさない
- テストのプロセスが権限の要る API を呼ぶと、強制終了される。この失敗は、不安定なテストとして扱わず、権限の境界の作りの問題として報告する
- インストール (アプリの置き換え) は、ユーザと合意したときだけ手順に入れる。状態を確かめるコマンドと同じ呼び出しにつながない
