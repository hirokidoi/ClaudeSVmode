# macOS で性能を測る

計測の一般的な作法は investigator のロール定義にある。ここは macOS の道具に限る。

- `ps -o %cpu` は、直近最大 1 分の減衰平均で、状態を変えた直後の値には前の状態が残る。`ps -o time` を間隔を空けて 2 回読んだ差を経過時間で割るか、`top -l 2` の 2 回目のサンプルを使う
- 直したのに数値が動かないときは、次の仮説を立てる前に、`sample` か `xctrace` (Time Profiler) で内訳を取る。待機中のフレームが大半のスレッドは読み飛ばす
- 描画は、受け取り側 (WindowServer) にも負荷を生む。自プロセスだけでなく、全プロセスを 2 点で読んだ系全体の差で見る。対照は、ウィンドウを閉じるより、音源を止めるなど「静かにする」ほうを選ぶ。閉じると、描画の存在とコミットが同時に消えて、切り分けにならない
- Apple Silicon では、同じ処理でも、P コアと E コアのどちらで走ったかで時間が大きく違う。比べる 2 点は、同じコア種別で取る
- 計測の手段が、値を押し上げないものを選ぶ。アクセシビリティ経由の問い合わせや、長い `sleep` を含むコマンドは、計測対象に影響することがある
- 「遅い」と言われたら、推測せず、段階ごとの時刻 (通知・判定・構築・開始・最初の入出力) を `os_log` で 1 回の操作から取る
- アプリの CPU が空いて見えても、並列化で速くなる根拠にならない。処理が OS 側で直列に回ることがある
