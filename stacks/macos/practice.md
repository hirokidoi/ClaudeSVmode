# macOS アプリの作法

## 配布方針

最初に配布方針を確かめる。署名の設定・entitlements・Hardened Runtime・サンドボックスの設定から読み取り、読み取れなければ「未確認」と書く。方針ごとに変わる点は次のとおり。

- ad-hoc 署名: 再ビルドのたびに別のアプリとして扱われ、TCC の許可とキーチェーンの確認が取り直しになる
- Developer ID と公証: 署名の同一性が保たれる。公証には Hardened Runtime が要る。`notarytool` で提出し、`stapler` で結果を添付する
- App Store: サンドボックスが必須になる。任意の場所の読み書きと、サブプロセスの起動が制約を受ける

## 権限 (TCC)

- API が空を返す、メインスレッドが止まって UI が出ないときは、実装を疑う前に、許可の状態とダイアログの待ちを疑う
- テストの実行プロセスは許可を持たない。権限が要る API は、差し替えられる境界の向こうに置き、既定の実装を持たせない。権限の状態を読む処理も同じ側に置く
- 実機でしか確かめられない操作 (権限の要る書き込み・ログイン項目の登録など) は、一覧にして明示する
- ログイン項目の登録は、承認待ちになりうる。表示は楽観的に更新せず、登録の結果にかかわらずシステムの状態を読み直して合わせる

## OS の挙動の確かめ方

- OS の API が何を返すかは、使い捨ての `swiftc` のコードで実機に問い合わせてから前提にする。一般知識で仮定して、ロジックや文書を書かない
- 「API に無い・書いていない」という主張は、SDK のヘッダを開いて確かめる。リポジトリの検索では裏付けにならない
- 通知やコールバックの届き方を確かめる計器は、本番と同じプロセスの形 (`NSApplication` を持つか) で作る。形が違うと、届かないという誤った結論になる

## 実機確認の前提

- 確認の前に、入っているバイナリの更新時刻、動いているプロセスの起動時刻、現在時刻を並べる。古いプロセスが動いたままだと、症状は「直っていない」と同じに見える
- `defaults` で設定を読む前に、実体の Info.plist でバンドル ID を確かめる。plist を直接読んでも、起動中の値とは限らない
- 統合ログは `/usr/bin/log` で呼ぶ。zsh では `log` が組み込みコマンドになる
- プロセスの有無は、名前で探さない。実行パス・`lsof` の cwd・接続で判断する

## 保存

- Codable の保存形式に非 Optional の項目を足すと、保存済みのデータが読めなくなる。足す項目は Optional にして、欠落を既定値と読む。改名やグループ分けも、削除と同じ扱いになる
- 永続データはアプリ専用のフォルダ (Application Support の下) に置き、素材ファイルの隣には書かない
- デバッグビルドは、保存先と設定ドメインをリリースと分ける

## スレッド

- ブロックしうる呼び出し (接続・外部コマンドなど) は、メイン以外で走らせる
- リアルタイムのスレッドでは、ロック・メモリ確保・ログを行わない

## 非公開 API

- 宣言して直接呼ばない。実行時に探して Optional で持ち、使えないときに他の機能へ波及しない形にする

## 見た目

- OS が描くコントロールは、版で見た目が変わる。スナップショットテストは OS の版に依存しうる
- レイアウトの変更は、推測で「直った」とせず、`screencapture` で撮って確かめる

## ビルドとスクリプトのレビュー観点

- `make` に `sudo` やホーム配下を消す操作を埋め込まない。`sudo` が要る操作は、コマンドを提示して利用者に任せる
- `rm` の対象が、空の変数で広がらない形にする
- テストが `~/Library/Preferences` に残す設定ファイルは、設定の常駐プロセスが書き戻し終えてから消す。接頭辞を直書きしたパターンで消し、変数にしない
