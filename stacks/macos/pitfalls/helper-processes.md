# 子プロセス・常駐の落とし穴

- 終了時は、送った要求への返事を待ってから止める。返事の前に接続が切れると、サービス側がクラッシュすることがある
- 止めるのは、アプリが起動したものだけにする
- 多重起動は、後から起動したほうが前のものを終了させて回復する形にすると、同じコマンドの再実行で必ず復帰できる。生存の判定は PID でなく、ロックで行う (PID の再利用による誤検知を避けられる)
- 常駐の生死は、プロセスやソケットファイルの有無でなく、実際に接続して判断する
- アプリを終了しても Dock に実行中と残るのは、配下のプロセスが居残っている状態。親が付け替わった (ppid が 1) プロセスを `ps -axo pid,ppid,lstart,command` で並べ、`lsof -a -p <pid> -d cwd` の cwd と起動時刻で、起動元を当てる
- アプリのバンドルの中に書き込む処理 (スクリプトのバイトコードのキャッシュなど) は、署名を壊す。同梱のスクリプトは、書き込まない設定で動かす
