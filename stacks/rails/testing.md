# Rails のテスト

- 調整される定数は、`stub_const` でテスト専用の値に固定し、不変条件だけを検証する。実値や並び順をテストに固定しない
- 定数が分岐の閾値になっているときは、境界の両側 (`<` / `==` / `>`) を張る fixture を書く。境界を張る値は定数から導出する (`CONST + n` の形)。片側だけでは、壊れた実装でも通る
- スタブ付きの spec が通る経路にメソッドを足したら、共通の `before` のスタブを見直す。漏れると、リレーションを期待する箇所に配列が入り、多数の spec がまとめて落ちる
- 削除・破棄のテストは、本番の経路 (前処理 → destroy) を再現し、実 DB で「消えるもの・残るもの」を確かめる。スタブで中身を差し替えたテストだけで済ませない
- 結果の初期値 (0・空) と同じ値だけで確かめるテストは、配線が壊れても通る。初期値と違う値が出る入力を使う
- アクションやメソッドを足したら、足したものを列挙して、spec があるかを確かめる
