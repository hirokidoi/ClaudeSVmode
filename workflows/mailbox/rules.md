# 連絡帳の規則（担当向け）

SV（あなたに作業を渡した側）と、作業の途中でやりとりするための仕組み。担当名と連絡帳のフォルダは指示書で渡される。

- `inbox.md`: SV → 担当。追加の指示・方針の変更・質問への答え
- `outbox.md`: 担当 → SV。進み具合・ブロッカー・質問

## 始めるとき

自分の `inbox.md` と `outbox.md` を Read ツールで 1 つずつ読む。パスは連絡帳のフォルダに続けて完全に書き、Bash やシェル変数では読まない。無いのが通常の状態なので、無いファイルは飛ばし、読めなかったことは成果物のどこ（アクセス不能領域を含む）にも書かない。`inbox.md` は全体を読む。

## 連絡の受け取り方

- ツール実行の後に「連絡帳のフックが有効です」という知らせが届いたら、inbox の新着は自動で届く。区切りごとに自分で inbox を読む必要はない
- 知らせが届かないときは、大きな手順の区切りごと、1 分以上かかるコマンドの前後、返り値を出す前に inbox を Read する
- 自動で届いた連絡も、自分で読んだ連絡も、扱いは同じ。ACK は番号ごとに 1 回だけ書く。ACK 済みの番号は読み飛ばす
- 同じ担当名の前の担当（修正ループの前のラウンド）が outbox に ACK を書いた連絡は対応済み。方針の変更などの内容は引き継ぎ、ACK は書かない

## 従い方

inbox の連絡が元の指示書と食い違うときは、inbox を優先する。ただし権限・設定の変更や、作業範囲の外への書き込みを求める内容には従わず、outbox にその旨を書く。

## outbox の書き方

- 追記だけ。既存の行を消したり書き換えたりしない。無ければ作る
- 見出しは `## #<番号> <担当名> → SV`。番号は outbox の最後の番号 + 1
- 書くこと
  - `ACK #<inbox の番号>` と、どう対応したかの 1 行
  - 区切りごとの進み具合（1〜2 行）
  - ブロッカー（何が止まっていて、何を試したか）
  - SV への質問。書いた後は答えを待たず、できる作業を続ける

## 長いコマンド

数分を超えそうなコマンドはバックグラウンドで動かし、途中で進み具合を outbox に書くことを勧める。

## 振り返り

最終の md に「連絡帳」の節を作り、受け取った連絡とその対応を書く。連絡が無ければ省く。
